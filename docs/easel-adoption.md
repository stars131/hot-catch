## 判断方法

只依据源码和实际运行结果做判断。README 中的技能数量、平台数量和 Star 数不作为效果证据。

Easel 是本地运行的 OpenClaw Agent + Python 脚本集合，星迹是多用户云端 Next.js 服务，两者的执行环境、权限边界和平台范围差异很大。吸收的标准：星迹现有链路里确实缺这一环，并且可以用确定性代码在现有架构内实现。

## 本批落地

### 1. 出站内容安全闸门

`lib/content/outbound-guard.ts`（前后端共用）与 `lib/content/outbound-guard-server.ts`（服务端）。

- **block**：模型服务 API Key、GitHub/AWS/Google/Slack 令牌、JWT、私钥、Bearer、中英文键值形式的口令、带口令的连接串、星迹自身的服务端配置名、当前部署敏感配置的真实值、未替换的 `{{变量}}` / `${变量}` / 【此处插入…】 / `[TODO]`。
- **warn**：本机或内网地址、通用密钥变量名、模型自称或「以下是为你生成的」、Markdown 与代码块残留、JSON 结构残留。
- 命中摘要中的密钥打码，检查结果本身不泄露真值。
- 「由 AI 生成」类标识不报警：平台与法规可能要求主动标注。Claude、Anthropic 等品牌词也不报警：星迹用户会写 AI 产品内容。
- 接入位置：发布就绪清单与对话就绪卡新增「公开信息安全」项；`preparePublishRecord` 对实际提交的标题和正文 fail-closed，返回 422；`submitPublishRecord` 首次提交前复查落库载荷，覆盖定时发布与旧记录，命中时记录 `CONTENT_GUARD_BLOCKED` 并不再提供无效的重试按钮。

### 2. 参考原文逐字重合

`lib/content/reference-overlap.ts`。

- 从 ReferenceBrief 快照取出原文摘录，以 10 个单位为窗口计算草稿中逐字重合的比例、最长连续长度和重合片段。空白与标点不计，换标点无法绕过。
- 重合 ≥ 20% 或连续 ≥ 20 个单位时提醒，并展示片段。参考可能是用户本人作品，因此只提醒、不阻塞。阈值是经验值，尚未用真实生成样本校准。

## 验证证据

| 项目 | 方式 | 结果 |
| --- | --- | --- |
| 闸门规则 | 单元测试（正例、反例、打码、字段定位、服务端抛错） | 通过 |
| 误报 | 对实时抓取的 2369 条公开热点标题与摘要（含 GitHub、HN、V2EX、掘金）扫描 | 星迹闸门 0 条命中；同语料 Easel 闸门 0 条 block、17 条 warn（均为正常科技新闻中的品牌词） |
| 发布入口拦截 | 集成测试，真实 PostgreSQL | 泄露密钥的版本返回 422 且不创建发布记录；被篡改的落库载荷在提交前标记失败，未联系供应商 |
| 就绪卡 | 集成测试 | 密钥让卡片阻塞且无确认动作；照搬参考给出重合提醒 |
| 界面 | Playwright 1440×900 与 390×844，生产构建 | 阻塞项定位到「第 1 页正文」，修改后实时解除；无横向溢出、无控制台错误 |

## 未验证

- 没有模型凭证，未用真实生成结果测量重合比例分布；阈值未校准。
- 没有 AiToEarn 凭证，真实发布链路中的拦截只在模拟模式与集成测试中验证。
- 发布中心提交失败时的拦截提示（toast）没有浏览器级验证，服务端返回内容由集成测试覆盖。
